System design

Architecture for an adaptive CEFR-based platform for Kinyarwanda, Swahili and French. The hard, differentiating part is the speech stack — native-accent TTS and pronunciation scoring — so the design isolates it behind one gateway and keeps everything else boring.

02 · Key flows
Pronunciation feedback · target < 3 s round-trip
client records Opus → signed-URL upload to S3 → POST /speech/score {item_id, audio_ref} → worker: STT + forced alignment vs reference → per-phoneme GOP + tone contour → verdict JSON → client renders syllable chips
Conversation turn · streamed over WS
user text or speech (→STT) → orchestrator: persona prompt + level cap + scenario goals → LLM reply → coach pass tags one correction max → TTS (persona voice) → stream {text, gloss, coach?, audio_url} → attempts logged async
Coach policy is product, not model: at most one correction per turn, always after a successful exchange — the design's “encourage first” rule enforced server-side.
Daily session build
GET /session/today → SRS picks due items (FSRS) → next lesson from roadmap position → one speaking task weighted to weakest skill → 25-min plan cached in Redis until completed

05 · Native voice pipeline — the differentiator
01
Record — 4–6 native speakers per language (mix of regions and ages), scripted sentences + free conversation, studio-quality, with written consent and revenue share. This corpus is an asset, not a cost.
02
Align & clean — segment, transcribe, force-align phonemes; the same alignment data later powers pronunciation scoring.
03
Fine-tune — multi-speaker TTS; keep speaker identity (“Diane · Kigali”) as a product feature, never a generic voice.
04
Native review loop — every generated clip batch is graded by native speakers before it enters the curriculum; failed clips go back to training.
05
Pre-render everything static — all curriculum audio rendered once to S3/CDN (quality-gated, cheap, instant). Live TTS only for dynamic conversation lines.
06 · Build order
M1–M2 · PROVE THE LOOP
Auth, curriculum tree (Kinyarwanda A1–A2 only), lesson player, SRS reviews, pre-recorded human audio — no models yet. Postgres + FastAPI monolith.
M3–M4 · SPEECH STACK
Whisper fine-tune + pronunciation scoring, TTS v1 from the recorded corpus, placement test, conversation over WS with one scenario pack.
M5+ · SCALE OUT
Swahili course + voices, French, B1 content, listening packs, week-1-vs-now archive, mobile PWA polish, vector-backed dynamic review.
DECISIONS WORTH ARGUING ABOUT
Monolith FastAPI until it hurts — services are modules, not microservices. Pre-rendered TTS over live synthesis wherever content is static. Whisper fine-tune before custom STT. FSRS over hand-rolled SRS. LLM via hosted API now; revisit self-hosting when conversation volume justifies a GPU pool.
